# 한국사 연표 스프린트

고1 한국사 기말고사 대비 암기 앱. 단일 HTML 파일이며 외부 의존성은 Google Fonts뿐이다.

## 출제 범위

2022 개정 한국사2 **Ⅰ단원 「일제 식민 통치와 민족 운동」 전체**(교과서 8~63쪽)를
소단원 단위로 옮겼다. 기본으로 켜져 있는 18개 단원이 이 범위다.

처음에는 01~03-1(8~33쪽)만 담았고, 뒤에 받은 교과서 34~63쪽으로 `s9`~`s18` 을 더했다.
새 범위의 사실·O·X·비교표·두문자·내신 문항은 한 원본에서 뽑아 세 앱에 똑같이 넣었다
(문장과 낱말은 교과서 본문을 따르고, 비교표의 굵은 낱말은 전부 원문에 있는지 대조했다).
그 원본이 `data-34-63.py` 다. 앱에는 이미 들어가 있으니 고칠 때만 연다.
교과서에 연도가 없는 사회·문화 변화(식민지 도시화, 모던 걸 등)는 연표에 가짜 연도를
박지 않으려고 사실 대신 O·X와 비교표로만 다룬다.

같은 사건의 새 사실로 **제자리에서** 갈아 끼웠다 — 사실 id 가 `"f"+순번`이라 줄을 지우면
뒤쪽 진도(간격 반복 상자)가 엉뚱한 사실로 옮겨 가기 때문이다. 새 사실은 `RAW` 맨 끝에
붙여 기존 id 를 하나도 건드리지 않았다.

예전 저장본은 불러올 때 새 소단원 열 개를 한 번 켜 준다(`S.rangeV`).

## 문제 유형

연표 사실 하나에서 4가지 문제를 자동 생성한다. 오답 선택지는 **같은 단원**에서만
뽑으므로 소거법으로 찍기 어렵다.

- `flash` 플래시카드 (자기 채점 3단계)
- `year` 사건 → 연도
- `event` 설명 → 사건명
- `cloze` 설명 속 핵심어 빈칸
- `order` 연표 정렬 — 4장을 순서대로 (5문제마다 삽입). 연도가 4개 이상 서로 다른
  단원에서만 출제한다 — 3·1 운동처럼 한 해에 몰린 단원은 순서를 물을 수 없다.
- `ox` O·X 함정 (직접 작성)

## 헷갈리는 짝 가려내기

시험이 노리는 건 「비슷해서 섞이는 둘」이다 — 개조파/창조파, 봉오동/청산리,
간도 참변/자유시 참변, 조선 혁명군/한국 독립군.

비교표(`COMPARE`)에는 이미 그 짝과 **구분 근거가 줄 단위로** 들어 있다. 그래서 새
문제를 적는 대신 그 줄을 그대로 낸다 — 한 줄을 보여 주고 **둘 중 어느 쪽이냐**만
묻는다. 범위 안에서 **147문항**이 나온다(비교표 22개 × 양쪽 줄). 새 범위의 비교표 12개 —
의열단/한인 애국단, 물산 장려/민립 대학, 문자 보급/브나로드, 암태도/원산, 6·10/광주 학생,
신민회/신간회, 민족주의 사학/사회 경제 사학, 박은식/신채호, 민족 혁명당/한국 국민당,
조선 의용대/한국광복군, 조선 독립 동맹/조선 건국 동맹, 카이로/포츠담 — 모두 답이 새는
줄 없이 문제가 된다.

- 답이 그대로 박힌 줄은 내지 않는다. 자기 쪽이든 상대 쪽이든 이름의 두 글자 이상이
  본문에 들어 있으면 거른다(`pgive()`) — 그래서 「서간도(삼원보): 경학사」 같은 줄은
  문제가 되지 않는다.
- **틀리면 비교표를 통째로 펴 준다.** 어디서 갈리는지 그 자리에서 보게.
- 「치트키」 탭 맨 위에서 시작한다. 비교표를 읽기만 하던 자리에 묻는 단계를 끼운 것이다.

## 간격 반복 (라이트너)

`BOX_DAYS = [0, 1, 3, 7, 16]`

정답이면 상자를 한 칸 올려 그만큼 뒤에 다시 출제하고, 오답이면 상자를 0으로
되돌려 같은 날 다시 낸다. 진도는 `localStorage`(`hansa-sprint-v2`)에 저장된다.

## 탭

`오늘`(복습 큐) · `연표`(정렬 게임 + 전체 연표) · `퀴즈`(무한 랜덤) ·
`치트키`(헷갈리는 짝 + 두문자 + 비교표) · `나`(통계 · 오답 노트 · 범위 · D-day)

### 연표 — 전체 순서로 쭉

기본은 **전체 순서**다. 단원 경계를 지우고 켜 둔 범위 전체를 일어난 순서대로 한 줄에
세운다. 시기가 바뀌는 자리(1910년 이전 · 1910년대 · 1920년대 · 1930~40년대 ·
1945년 이후)마다 검은 머리표가 들어가고, 줄마다 갈래를 색과 꼬리표로 나눈다 —
일제가 한 일(빨강 · `일제`), 우리가 한 일(청록 · `우리`), 바깥 세계(파랑 · `세계`),
그 밖(회색). 둘이 어떻게 맞물리는지가 이 화면의 요점이다.

**소단원별로** 를 누르면 예전처럼 소단원 머리표로 끊어서 본다.

장려회 조직」에 맞춰 1920으로 바로잡았다.)

## 디자인 — HANSA OS

세 앱(`index.html` · `monsters.html` · `learn.html`)이 같은 껍데기를 쓴다.
1985년식 픽셀 데스크톱 OS를 본떠, 자둣빛 바탕 위에 크림색 창이 뜨고 위에는 가짜 OS
표시줄(로고 · 앱 이름 · 실시간 시계)이, 아래(넓은 화면에서는 창 밑)에는 장치 아이콘
독이 붙는다. 창 제목은 경로로 표시된다 (`/TODAY` · `/TIMELINE` · `/QUIZ` · `/CHEAT` · `/ME`).

- **모서리 없음** — `border-radius:0!important`
- **3px 검정 테두리 · 블러 없는 4px 하드 그림자**
- **눌리는 버튼** — 안쪽 하이라이트/그림자로 입체를 내고, `:active`에 그림자만큼 밀어 넣는다
- **디더링 무늬** — `repeating-linear-gradient`로 줄무늬와 점선을 만든다
- 독 아이콘 다섯 개는 16×16 격자에 `<rect>`를 찍어 그린 인라인 SVG다

### 서체

한글 픽셀 폰트는 Google Fonts에 없다(갈무리·둥근모 모두 미제공). 그래서 나눠 쓴다.

| 용도 | 서체 |
|---|---|
| 영문·숫자 크롬 (창 제목, 시계, 연도, 라벨) | `Press Start 2P` |
| 한글 제목 | `Do Hyeon` |
| 한글 본문 | `Gothic A1` |

### 단일 세계관

라이트/다크 전환을 버리고 이 화면 하나로 통일했다. 모든 색을 직접 칠하므로 보는
사람의 테마와 무관하게 같은 모습이 나온다. 대비는 제목 14.13:1 · 본문 7.30:1 ·
딱지 11.82:1 · 상단바 14.13:1로 전부 기준을 넘긴다.

단원 숙련도 막대는 색이 아니라 **길이**가 크기를 나른다. 잘함/보통/약함을
초록·황토·빨강으로 칠하면 정상 시야에서도 빨강↔황토 구분이 어렵기 때문에(ΔE 기준
미달) 단일 색으로 두고 약한 단원만 「약함」 글자 배지로 짚는다. 아직 한 번도 풀지
않은 단원에는 배지를 붙이지 않는다.

## 읽히는 글자

작은 회색 글씨(수업 제목표·설명 꼬리말·「눌러서 확인」 같은 7.5~13.5px 라벨)가
바탕과 3.16~3.57:1 밖에 안 나와 WCAG AA(4.5:1)에 못 미쳤다. `--ink-3` 을
`#8B7A96` → `#6E5C7A` 로 내려 크림 5.47:1 · 패널 4.84:1 로 맞췄다. 중간 톤
(`--ink-2` 7.30:1)과의 위계는 그대로다.

색이 붙은 글씨도 한 번 더 훑었다. 노란 형광 위 청록 인과 사슬 제목(2.52:1),
사실 카드의 「왜?」·「그래서」 라벨(4.17 · 3.31:1), 비교표의 붉은 제목(4.09:1),
오답 배너의 숫자(3.42:1)가 모두 미달이었다. 짙은 짝(`--jade-d` #1D5C52,
`--blue-d` #2A4D85, `--red-d` #B0342C)을 만들어 글씨에만 쓰고, 테두리·배경은
원래 색을 그대로 두어 화면 인상은 바뀌지 않게 했다.

정답·오답을 고른 뒤의 화면도 마찬가지였다. 「연표 스프린트」의 정답 칸은 흰 글씨가
4.06:1, 오답 칸의 번호는 3.42:1 이었다. 바탕을 한 단계씩 내려(#2F8C7E → #257366,
#D2453B → #B0342C) 5.64 · 4.72 로 맞췄다.

홈·오답·복습·연표·대조표·내신·서술형·헷갈리는 짝과 카드 다섯 유형, 그리고 문제를
푼 뒤의 화면까지 실제 브라우저에서 훑어 남은 미달은 **일부러 흐려 둔 정답 카드
하나뿐**이다.

## 성능

세 앱 모두 단일 HTML 파일이라 눈에 띄는 병목이 둘 있었다. 둘 다 재서 고쳤다.

### 글꼴이 첫 화면을 막고 있었다

`<link rel="stylesheet">` 로 건 Google Fonts 가 렌더를 막는다. 망이 느리거나
막혀 있으면 **글꼴을 다 기다린 뒤에야** 화면이 뜬다 — 측정해 보니 첫 화면까지
**12.6초**였다.

링크를 `media="print"` 로 걸어 렌더에서 빼고, 다 받은 뒤에 `media="all"` 로
갈아 끼운다. 안 오면 대체 글꼴로 그냥 쓴다.

| 첫 화면까지(DOMContentLoaded) | 이전 | 지금 |
|---|---|---|
| `index.html` | 12,957ms | 60ms |
| `learn.html` | 12,574ms | 33ms |
| `monsters.html` | 12,589ms | 100ms |
| `hansa.html` | 12,931ms | 202ms |

### 긴 목록이 화면 밖까지 배치되고 있었다

치트키 26장·연표 105줄·찾기 결과 60개처럼 한 화면을 넘는 목록은, 안 보이는
부분까지 배치하느라 화면 전환이 느렸다. `content-visibility:auto` 로 화면 밖은
건너뛰게 하고 `contain-intrinsic-size` 로 자리만 잡아 둔다.

| 화면 전환 | 이전 | 지금 |
|---|---|---|
| 치트키 (26장) | 51.1ms | 2.9ms |
| 연표 (105줄) | 23.0ms | 3.7ms |
| 찾기 결과 (60개) | 49.5ms | 4.5ms |
| 인물 도감 (32장) | 3.7ms | 1.6ms |
| 몬스터 목록 (60마리) | 16.5ms | 6.2ms |

### 재 보고 안 고친 것

- **JS 는 이미 빨랐다.** 색인·문제 뽑기·정답 확인 전부 5ms 아래다.
  `buildIndex()` `timeline()` `choPool()` 은 이미 캐시하고 있었다.
- CSS 를 하나씩 꺼 가며 재 봤지만 `image-rendering` · `border-radius!important` ·
  하드 그림자 · 고정 배경 어느 것도 유의미하지 않았다. 같은 측정을 다섯 번 반복하니
  48.7 → 59.3ms 로 흔들려서, 그 정도 차이는 전부 측정 잡음이었다.
  **비용은 요소 개수였고, 답은 안 보이는 걸 안 그리는 것이었다.**

## 개발

빌드 과정이 없다. `index.html`을 브라우저로 열면 된다.
데이터를 고치려면 `RAW` / `OXRAW` / `COMPARE` / `MNEMO` 배열을 편집한다.
`cloze` 문제가 나오려면 설명(`d`) 안에 빈칸 키워드(`k`)가 그대로 들어 있어야 한다.

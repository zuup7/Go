# 🎤 차트런 (Chart Run!)

**100위에서 시작해 1위까지 달린다.** 마리오처럼 달리고 뛰어서 음원차트 정상에 오르는
픽셀 플랫포머입니다. 앨범 17장이 길을 막고, 정상 직전에는 그 열일곱 장이
**하나로 합체해 최종 보스**가 됩니다.

이미지 파일도, 음원 파일도, 외부 라이브러리도 없습니다. 전부 코드로 그리고 코드로 냅니다.

**화면에 나오는 글자는 숫자뿐입니다.** 순위·재생수·차트아웃 횟수·시간·스테이지 번호.
대사도, 사망 문구도, 스테이지 이름도 없습니다 — 무슨 일이 벌어지는지는 화면이 말합니다.

## 실행하기

```bash
npm start              # http://localhost:5173/chartrun/ 에서 플레이
npm test               # 게임 규칙 테스트
npm run build:chart    # 서버 없이 열리는 chartrun/dist/play.html 한 파일 생성
```

> `index.html` 을 파일로 직접 열면 ES 모듈 때문에 동작하지 않습니다.
> 서버 없이 즐기려면 `npm run build:chart` 로 만든 한 파일을 여세요.

## 조작

| 키 | 하는 일 |
|---|---|
| `←` `→` / `A` `D` | 이동 |
| `Space` / `↑` / `W` | 점프 — **길게 누를수록 높이 뜬다** |
| `C` / `K` / `Shift` | **대시** (보스전) — 바라보는 쪽으로 한 발 옆으로 |
| `X` / `J` / `↓` | 마이크 던지기 (보스전) |
| `R` | 그 자리에서 다시 시작 |
| `Esc` / `P` | 일시정지 (메뉴가 뜹니다) |
| `M` | 음소거 |

### 일시정지

`Esc` 또는 화면 오른쪽 위 **⏸** 를 누르면 판이 서고 메뉴가 뜹니다.
◀▶ 로 고르고 점프로 확인하며, **줄을 직접 눌러도 됩니다** — 폰에는 ◀▶ 도 엔터도 없습니다.

| 줄 | 하는 일 |
|---|---|
| 이어하기 | 그대로 이어서 |
| 체크포인트부터 다시 | `R` 과 같은 길 |
| 소리 n% | 누를 때마다 0 → 25 → 50 → 75 → 100 한 칸씩 (음소거와는 별개) |
| 타이틀로 | 판을 접고 나갑니다 |

멈춘 동안에는 시간도 흐르지 않고 아무것도 움직이지 않습니다. **타이틀로 나갈 때 멈춤이
같이 풀리는지**를 테스트가 지킵니다 — 멈춘 채로 장면이 바뀌면 아무 키도 안 먹어서
게임이 영영 잠깁니다.

⏸ 버튼도 다른 화면 버튼처럼 **끌어 옮기고 크기를 바꿀 수 있습니다.**

### 개발자 모드 — 스테이지 골라 들어가기

평소에는 **1스테이지부터 쭉** 깹니다. 보스전만 다시 보고 싶을 때 초원부터 다시 달리기는
번거로우니, 타이틀 구석의 **⚙** 를 누르고 **1234** 를 넣으면 스테이지 선택이 열립니다.
숨기려고 만든 게 아니라 실수로 눌리지 않게 하려고 만든 것이라 암호랄 것도 없습니다.

- 스테이지 넷 + 보스전을 바로 고를 수 있고, 🎬 오프닝도 다시 볼 수 있습니다.
  마지막 칸에서 개발자 모드를 다시 끕니다.
- **골라 들어간 판은 기록을 갱신하지 않습니다.** 보스만 골라 이기고 최고 기록이 되면
  기록이 거짓말이 됩니다. 죽은 횟수만 그대로 쌓입니다.
- 3스테이지로 들어가면 순위도 그 자리(#20)에서 시작합니다.

### 휴대폰 — 가로로 꽉 차게

폰에서는 **게임이 화면을 꽉 채웁니다.** 조작 버튼은 화면 아래에 자리를 따로 차지하지 않고
좌우 검은 여백과 화면 구석에 반투명으로 겹쳐 뜹니다 — 아래에 버튼 줄을 깔면 정작 게임이
손톱만 해집니다. 보스전에서는 🎤 던지기 버튼이 하나 더 나옵니다.

**세로로 들고 있으면 화면을 통째로 눕힙니다.** 회전 잠금을 켜둔 사람이 많아서
"가로로 돌려주세요" 라고만 써두면 아무 일도 일어나지 않기 때문입니다. 폰을 옆으로 돌려 잡으면
그때부터 똑바로 보입니다.

버튼 위에서 **엄지를 미끄러뜨려도 됩니다.** ◀ 에서 ▶ 로 밀면 그대로 방향이 바뀝니다
(누른 채로 미끄러뜨리면 이전 버튼이 눌린 채 남는 게 흔한 버그입니다).

### 버튼 자리와 크기는 직접 정합니다

손 크기도 잡는 법도 사람마다 다릅니다. 화면 구석의 **✥** 를 누르면 편집 모드가 되고,
버튼을 **끌어다 원하는 자리에 놓으면** 됩니다. 기기에 저장돼서 다음에도 그대로이고,
`처음대로` 로 되돌립니다.

| 편집 바 | 하는 일 |
|---|---|
| **− / +** | 크기 70%~180%. 버튼을 하나 **눌러서 고르면 그 버튼만**, 아니면 전체 |
| `전체` | 고른 버튼을 놓고 전체 조절로 돌아간다 |
| `투명도` | 40 / 60 / 80 / 100% — 진하면 앞이 안 보이고 흐리면 어디를 누르는지 모른다 |
| `좌우 바꾸기` | 버튼을 통째로 거울처럼 뒤집는다 (왼손잡이) |
| `처음대로` | 자리·크기·투명도를 전부 되돌린다 |

점프만 크게 쓰는 사람이 있고 방향키만 크게 쓰는 사람이 있어서 **버튼별로** 조절합니다.
고른 버튼은 초록 테두리로 표시됩니다.

크기를 키우면 가장자리에 붙여둔 버튼이 자동으로 안쪽으로 밀려 들어옵니다 —
화면 밖으로 삐져나가면 아예 누를 수가 없기 때문입니다.
크기는 슬라이더가 아니라 버튼입니다. 눕힌 화면은 90도 돌아가 있어서 끌기 좌표가 틀어집니다.

- 편집하는 동안에는 **게임이 멈춥니다** — 옮기다가 죽으면 억울합니다.
- 자리는 픽셀이 아니라 **비율**로 저장해서, 화면 크기가 달라져도 같은 자리에 남습니다.
- **가로로 든 것과 세로로 눕힌 것은 따로 기억합니다.** 좌표계가 90도 틀어져 있어서
  한쪽에서 잡은 자리를 다른 쪽에 그대로 쓰면 엉뚱한 데로 갑니다.
- 앱이 화면 위아래에 얹는 것들(아티팩트 뷰어의 닫기 X, 안드로이드 내비게이션 바) 밑으로는
  **아예 못 옮깁니다.** 거기 두면 눌리지도 않고, 누르려다 게임이 닫힙니다.

### 손에 붙는 이유

| 장치 | 하는 일 |
|---|---|
| 코요테 타임 | 발판을 살짝 벗어나도 8프레임 동안은 점프가 된다 |
| 점프 버퍼 | 착지 직전에 누른 점프를 10프레임 기억했다 발동한다 |
| **모서리 보정** | 머리 귀퉁이가 블록에 5px 이하로 스치면 옆으로 밀어 통과시킨다 |
| **정점 체공** | 점프 꼭대기 근처에서 중력이 약해져 겨눌 틈이 생긴다 |
| **빠른 낙하** | 내려올 때는 중력이 1.45배 — 붕 뜨는 느낌이 사라진다 |
| **방향 전환 가속** | 가던 방향의 반대를 누르면 2.1배로 꺾인다 |
| **누른 채 밟기** | 밟는 순간 점프를 누르고 있으면 1.4배로 튄다 |
| **찌그러짐** | 착지에 납작, 점프에 길쭉 — 누른 게 화면에 바로 보인다 |
| **착지 먼지** | 세게 떨어졌을 때만 발밑에 먼지가 인다 |
| **대시** | 바라보는 쪽으로 0.13초 동안 2.1배 속도 (약 34px). 쿨 0.7초. **보스전에서만** |
| **걸음** | 발이 **시간이 아니라 달린 거리**로 돈다 — 느리게 걸어도 발이 안 미끄러진다 |

**누른 채 밟기**가 특히 중요합니다. 밟기가 "닿으면 알아서 튀는 것"이 아니라
**노려서 쓰는 이동 수단**이 됩니다 — 앨범을 밟고 높은 발판으로 올라가는 길이 여기서 나옵니다.

### 그림 여덟 장

주인공은 프레임이 **여덟 장**입니다: 섬 · 달리기 네 장 · 점프 · 낙하 · 대시.
다리만 바뀌던 시절에는 몸통이 고정이라 미끄러지듯 보였습니다. 지금은 **머리·팔·다리가
같이** 움직입니다 — 달릴 때는 머리가 앞으로 숙고 팔이 번갈아 흔들리며, 발이 땅에 닿는
프레임에서는 상체가 한 칸 눌려 걸음마다 위아래로 까딱입니다.

**발은 시간이 아니라 달린 거리로 돕니다** (`player.stride`). 시간으로 돌리면 느리게 걸을 때
발이 땅을 미끄러지고, 벽에 막혀 제자리인데도 발만 계속 돕니다. 실제로 움직인 픽셀을 재서
9px마다 한 칸 넘기므로 **속도가 어떻든 발과 땅이 어긋나지 않습니다.** 공중에서는 안 돕니다 —
허공에서 발이 돌면 뛰는 게 아니라 헤엄치는 것처럼 보입니다.

뜰 때와 떨어질 때도 그림이 다릅니다. 뜰 때는 팔이 위로, 떨어질 때는 균형 잡느라 옆으로
벌어집니다. 대시는 몸을 앞으로 쏠리게 하고 두 팔을 뒤로 젖힌 자세에, 지나온 쪽으로
잔상 두 장이 옅게 따라붙습니다.

찌그러짐은 그림만 늘였다 줄이는 것이고 물리는 그대로입니다. 조작이 화면에 즉시 보이는 게
조작감의 절반입니다.

**대시는 보스전에서만 나갑니다.** 스테이지 1~4 는 걷기와 점프만으로 넘도록 짜여 있어서,
판에서도 대시가 되면 구멍이 구멍이 아니게 되고 넘으라고 만든 자리를 그냥 지나쳐 버립니다.
대시가 있어야 하는 건 아레나 하나뿐입니다 — 3페이즈 레이저를 비켜서는 자리.

**거리는 34px, 두 칸 남짓으로 짧게 잡았습니다.** 더 멀리 가면 순간이동처럼 보여서
어디에 설지를 겨눌 수가 없습니다. 짧게 끊어야 "한 발 옆으로"가 되고, 그게 겨눌 수 있는
움직임입니다. 레이저 발자국(14px)을 벗어나는 데는 이만큼이면 충분합니다.

**무적은 없습니다.** 순수한 속도뿐입니다. 무적을 주면 앨범도 탄막도 보스 몸도
전부 통과해서, 닿는 것이 무섭지 않은 게임이 됩니다 — 이 게임의 절반이 거기서 무너집니다.
그래서 대시는 **뚫는 수단이 아니라 비켜서는 수단**입니다. 공중에서도 쓸 수 있지만
**중력은 그대로**라, 거리를 버는 도구지 나는 도구가 아닙니다.
쿨이 도는 동안에는 발밑에 막대가 차오르고, 폰에서는 💨 버튼이 흐려집니다.

**대시는 누른 방향으로 나갑니다.** 폰에서는 ◀ 와 💨 가 한 프레임에 같이 들어오는 게
보통이라, 보고 있던 쪽만 따지면 **피하려던 반대쪽**으로 대시해서 레이저 안으로 들어갑니다.

**한 대 맞은 뒤 1.2초는 내가 무적입니다.** 예전에는 그냥 일정하게 깜빡이기만 해서
**언제 끝나는지** 알 수가 없었고, 그래서 안전한 줄 알고 뛰어들었다 그 자리에서 또 맞았습니다.
지금은 끝이 가까울수록 **깜빡임이 빨라지고**, 몸을 두른 **하늘색 테가 같이 옅어집니다** —
테가 사라지는 게 곧 무적이 끝나는 순간이라 눈으로 세고 있을 수 있습니다.

이 숫자들을 만지면 레벨이 조용히 못 깨는 판이 될 수 있어서, **달리며 뛰면 세 칸 구멍을 넘고
두 줄을 오른다**는 것을 테스트가 직접 시뮬레이션해서 확인합니다.

## 오프닝 — 왜 달리는가

처음 시작하면 **12초짜리 오프닝**이 뜹니다. 대사는 없습니다.

좁은 방, 책상 위 마이크 하나, 그리고 **옆에 앉은 강아지 공주.**
음표가 하나 떠오르고, 위로 빨려 올라갑니다.
차트 순위표가 내려오고 — 맨 아래 **`#100`** 칸에 내가 걸립니다.
위를 훑어보면 앨범들이 끝없이 쌓여 있고, 하나같이 나를 내려다봅니다.
그중 하나가 방까지 내려와 **그녀를 채갑니다.** 뛰어올라 손을 뻗지만 놓칩니다.
마이크를 쥐고 달려나갑니다.

### 그래서 1위로 가는 길이 곧 그녀를 되찾는 길입니다

납치가 이야기를 끝까지 꿰맵니다. 안 그러면 마지막에 처음 보는 강아지와 갑자기 결혼합니다.

| 어디 | 그녀는 |
|---|---|
| 오프닝 | 앨범이 채간다 |
| 합체 컷신 | 소용돌이에 같이 휘말리고, 합쳐진 원반 위에 새장이 얹힌다 |
| 보스전 | 싸우는 내내 보스 머리 위에 갇혀 있다 |
| 엔딩 | 보스가 터질 때 새장이 부서지고 풀려난다 → 결혼식 |

**격파가 곧 구출**이라는 규칙은 `princessCaged(boss)` 한 곳에만 있습니다
(`src/core/boss.js`). 그리는 쪽은 상태를 따로 안 들고 이걸 물어봅니다.

- **한 번만 뜹니다.** 그 다음부터는 예전처럼 곧장 스테이지 1 입니다
  (`save.seenOpening`). 언제든 건너뛸 수 있습니다.
- 다시 보려면 **개발자 모드 → 🎬 오프닝 다시 보기**.
- 마지막에 스테이지 브금으로 갈아타므로, 스테이지 1 이 시작될 때 음악이 이미 흐릅니다.

## 순위가 곧 진행도

화면 왼쪽 위의 **`#숫자`** 가 지금 순위입니다. 오른쪽으로 갈수록 숫자가 줄어듭니다.

| 스테이지 | 무대 | 순위 |
|---|---|---|
| 🌿 STAGE 1 | 초원 — 언덕과 구름, 들꽃 | 100위 → 50위 |
| 🌳 STAGE 2 | 숲 — 나무 줄기 사이로 빛줄기 | 50위 → 20위 |
| 🏢 STAGE 3 | 건물 안 — 창문 격자와 기둥, 형광등 | 20위 → 5위 |
| 🪜 STAGE 4 | 차트 정상 계단 | 5위 → 2위 |
| 👑 BOSS | 1위 앞 | 2위 → **1위** |

무대 그림은 `stage.theme` 이 고르고 색은 `stage.sky / far / ground` 에서 옵니다
(`src/render/scene.js`). 둘이 나뉘어 있어서 같은 무대를 낮/밤으로 바꾸는 것도 색만 갈면 됩니다.

## 앨범 17장 — 아홉 가지 성격

밟으면 죽는 놈, 갈라지는 놈, 떨어지는 놈이 따로 있습니다.

| 행동 | 하는 짓 | 예시 |
|---|---|---|
| `walker` | 좌우 순찰, 낭떠러지에서 돌아섬 | 데뷔 싱글, 밀리언셀러 |
| `hopper` | 주기적으로 내 쪽으로 폴짝 | 리메이크 앨범, 트로트 대작 |
| `flyer` | 사인파로 공중을 떠다님 | 여름 시즌송, 새벽 자작곡 |
| `charger` | 같은 높이에 들어오면 돌진 | 아이돌 컴백작, 광고 삽입곡 |
| `shooter` | 음표 탄환을 쏨 | 감성 발라드, 랩 믹스테잎 |
| `spinner` | 회전하며 낭떠러지도 무시하고 달림 | 클럽 리믹스, 페스티벌 헤드라이너 |
| `dropper` | 머리 위에서 기다리다 떨어짐 | 조명 아래 라이브, 드라마 OST |
| `shielder` | **위에 가시** — 밟으면 내가 죽음 | 알고리즘 추천, 레전드 명반 |
| `splitter` | 밟으면 작은 앨범 둘로 갈라짐 | 컴필레이션 |

**밟으면 안 되는 놈**은 위에 **흰 가시 세 개**가 박혀 있습니다 (`shielder`).

**한 번 밟아도 안 죽는 놈**은 그것대로 따로 알려줘야 합니다. `밀리언셀러`는 체력이 2라
한 번 밟으면 튕기기만 하고 살아남는데, 표시가 없으면 **단단해서인지 무적이라서인지**
알 수가 없어서 "밟아도 안 죽는 놈"으로 오해하고 그냥 피해 가게 됩니다. 그래서 머리 위에
**남은 대수만큼 금색 점**을 띄우고, 아직 한 대도 안 맞았으면 **금테**를 둘렀습니다 —
한 대 먹이면 테가 벗겨지고 점 하나가 꺼져서 **진행이 눈에 보입니다.**

> 점은 **밟을 수 있는 놈에게만** 답니다. 가시 달린 놈은 애초에 밟아서 깎을 방법이 없어서,
> 거기에 체력을 띄우면 "몇 대 때리면 죽는다"는 **거짓말**이 됩니다.

**덤비기 전에는 반드시 예고가 있습니다.** 돌진형은 달려들기 전 눈썹을 번쩍이며 부르르 떨고,
낙하형도 떨어지기 직전에 흔들립니다. 사격형도 쏘기 직전 **멈춰 서서 눈썹을 번쩍입니다** —
탄이 날아오고 나서야 알면 피할 방법이 없습니다. 예고 없이 들어오면 피할 방법이 없어서 트롤이 아니라
그냥 불합리한 게임이 됩니다. 또 모든 앨범은 **배치된 자리 근처에서만 순찰**합니다 —
안 그러면 벽을 만날 때까지 흘러가서 레벨 디자인이 통째로 무너집니다.

> 앨범 커버는 **진짜 사진 16장**입니다 (`assets/albums/`). 17번만 아직 사진이 없어서
> 코드로 그린 무늬가 나옵니다. 바꾸거나 더 넣는 법은
> [`assets/albums/README.md`](assets/albums/README.md) 에 있습니다.

## 트롤 함정 — 살짝 고양이마리오

보스전 전까지는 정직한 길이 아닙니다. 다만 **목숨은 무한**이고,
**한 번 당한 함정은 그 뒤로 화면에 붉게 표시**돼서 외우면 반드시 넘어갑니다.

- **가짜 발판** — 밟는 순간 사라진다. 하필 그 위에 음표가 놓여 있다.
- **낙하 앨범** — 아래를 지나가면 머리 위에서 떨어진다.
- **역주행 바닥** — 올라서면 왼쪽으로 밀린다.
- **낚시 블록** — `?` 인 줄 알고 쳤더니 리믹스가 튀어나온다.
- **투명 블록** — 안 보이는 벽이 점프 궤도를 막는다.
- **불쑥 가시** — 평범한 땅인 척하다가 지나가면 솟는다.
- **도망가는 골** — 다가가면 달아난다. 진짜 깃발은 따로 있다.
- **무너지는 바닥** — 멀쩡한 땅인 척하다 올라서면 부르르 떨다 꺼진다. 멈추면 떨어진다.
- **솟아오르는 벽** — 달리다 보면 앞에서 벽이 쿵 하고 솟는다. 두 칸이라 넘을 수는 있다.
- **역재생 구간** — 4초간 **좌우가 뒤바뀐다.** 차트 게임다운 트롤.
- **정전** — 스트리밍 서버가 나가고 3.5초간 내 주변만 빼고 깜깜해진다.

죽으면 **차트아웃 횟수**가 하나 올라갑니다. 이 숫자는 엔딩까지 따라와서 자랑거리가 됩니다.

> 하드모드에는 함정 여섯 종이 더 있습니다 — 아래 «하드모드» 절.

## 합체 컷신과 최종 보스

스테이지 4를 통과하면 컷신이 시작됩니다. 열일곱 장이 화면 중앙으로 빨려 들어가
소용돌이치다 하나로 뭉치고, 보스가 등장합니다. **컷신에 대사는 없습니다.**

**보스를 때리는 두 가지 방법**

- 🎤 **던지기** — 보스가 주기적으로 마이크를 흘립니다. 주워서 `X` 로 던지면 멀리서 안전하게 한 대.
  **한 번 쓰면 없어지므로** 다음 드롭까지 기다려야 합니다.
- 👟 **밟기** — 가운데 **재생 버튼**이 초록으로 열릴 때만 밟을 수 있습니다. 붙어야 해서 위험하지만
  마이크를 기다릴 필요가 없습니다.

체력은 **9** — 페이즈당 세 대입니다. 체력계는 보스 바로 아래에 붙어 다녀서 화면을 가리지 않습니다.

보스전은 체력에 따라 세 페이즈로 넘어갑니다. 페이즈는 절대 뒤로 가지 않고, 바뀔 때마다
**전환 컷신**이 끼어듭니다. 컷신이 도는 동안에는 보스도 탄도 나도 완전히 멈추므로
연출 보다가 맞아 죽는 일은 없습니다. 확인 키로 건너뛸 수 있습니다.

1. 부채꼴로 탄을 뿌립니다. 주기적으로 가운데 **재생 버튼**이 초록으로 열리는데,
   그때만 밟을 수 있습니다.
2. 네 조각으로 갈라져 화면을 가로지릅니다. 탄도 빨라집니다.
3. 잡몹 앨범을 계속 소환하며 패턴이 가장 빨라집니다. 그리고 **레이저**를 씁니다 (아래).

### 3페이즈 레이저 — 로봇만 할 수 있는 것

수치만 올라간 공격을 아무리 얹어도 "최종 형태"로 안 읽힙니다. 합체 로봇이 되었으면
**로봇만 할 수 있는 기술**이 하나는 있어야 합니다.

가슴 코어 — 약점으로 열리는 바로 그 구멍 — 에서 **빛기둥**이 바닥까지 뻗고,
**옆으로 훑고 지나갑니다.** 같은 구멍이 쏘고, 같은 구멍이 열립니다.

| 단계 | 화면 | 아픈가 |
|---|---|---|
| **예고 (0.9초)** | 보스가 **멈춰 서고**, 흰 선이 바닥까지 내려옵니다. 바닥에는 **기둥이 설 자리**가 폭 그대로 뜹니다 | **아니요** |
| **발사 (1.6초)** | 굵은 기둥이 되어 옆으로 훑습니다 | 예 |

**못 피하는 공격은 트롤이 아니라 그냥 불합리한 게임입니다.** 그래서 셋을 지킵니다.

1. **보스가 멈추는 것 자체가 예고입니다.** 큰 걸 쓰기로 한 놈은 돌아다니지 않습니다.
2. **훑는 속도(96px/s)가 달리기(124px/s)보다 느립니다.** 달려서 도망칠 수 있습니다.
   테스트가 이 부등호를 직접 지킵니다 — 수치를 만지다 뒤집히면 못 피하는 판이 됩니다.
3. **훑는 거리가 아레나보다 한참 짧습니다.** 끝까지 밀려 구석에 갇히는 일이 없습니다.

훑는 방향은 **예고 시점에 내가 서 있는 쪽**입니다. 쫓아온다는 게 읽혀야
피해야 하는 것이 되지, 안 그러면 그냥 배경 효과로 보입니다.

> 예고선은 **안 아픕니다.** 예고에 맞아 죽으면 그건 예고가 아닙니다.
> 판정과 그림은 `core/boss.js` 의 `laserBeam()` **하나**를 같이 봅니다 —
> 사각형을 양쪽에 따로 적으면 언젠가 보이는 자리와 죽는 자리가 어긋납니다.

기둥은 발판(높이 160) 자리를 지나갑니다. 올라선다고 피해지지 않습니다.
**대시로 발자국 밖으로 비켜섰다가, 훑고 지나가면 곧바로 보스 밑으로 돌아와 밟습니다.**

**전환 컷신**
1. **페이즈 2** — 보스가 부르르 떨다 금이 가고 네 조각으로 쪼개진다
2. **페이즈 3** — 가짜 실시간 차트가 뜨고, 꼴찌였던 보스가 대놓고 1위로 솟는다.
   그리고 그 힘으로 **합체한다** — 2페이즈에서 쪼개졌던 조각이 사방에서 불려와
   팔·다리·머리가 차례로 붙고, 가슴 코어에 불이 들어온다.
   조작이 합체의 **이유**라 순서가 정해져 있다 (`rig` → `call` → `assemble` → `core`).

   합체한 뒤로는 원반이 아니라 로봇으로 싸운다. 궤도를 도는 조각도 파편이 아니라
   **로켓 펀치**로 바뀐다 — 합쳐놓고 파편이 날아다니면 앞뒤가 안 맞는다.
   약점은 그대로 가운데 재생 버튼이고, 로봇에서는 가슴 코어가 된다.
   원반으로 그릴지 로봇으로 그릴지는 `bossCombined(boss)` 하나가 정한다
   (`src/core/boss.js`) — 페이즈는 뒤로 안 가므로 한 번 합체하면 안 풀린다.

쓰러뜨리면 **엔딩 컷신**이 이어집니다. 18초, 2부로 나뉩니다.

**1부 — 1위** 보스가 터지며 앨범 열일곱 장이 사방으로 흩어지고, 그 중 다섯 장이 2위부터
아래로 줄을 섭니다. 맨 윗줄만 비어 있고, 거기에 내가 올라서면 **#1** 이 박힙니다.

**2부 — 결혼식** 차트 순위표가 그대로 식장이 됩니다. 줄 서 있던 앨범 열일곱 장이 하객이 되어
붉은 카펫 양옆에 앉고, 1위 자리에는 꽃 아치가 섭니다. **연갈색 말티푸 강아지 공주**가
카펫을 따라 걸어 들어와 왕관 쓴 나와 마주 서고, 둘 사이로 반지가 떠오르고, 하트와 축포로 끝납니다.

그 다음 통계 화면에서 걸린 시간, 차트아웃 횟수, 물리친 앨범 수, 찾은 함정 수, 모은 재생수를
보여줍니다. 최고 기록을 깼으면 시간 옆에 **신기록**이 붙습니다 — 표시와 저장이 어긋나지 않게
`beatRecord()` 한 함수가 둘 다 판단합니다. 타이틀에도 `BEST #순위 · 최고 기록`이 뜹니다.
컷신은 언제든 건너뛸 수 있습니다.

### 컷신에도 소리가 붙습니다

터지고, 줄 서고, 반지가 떠오르는 순간마다 소리가 납니다. 결혼식이 시작되면
**웨딩 마치**로 갈아탑니다 — 느리고, 킥도 하이햇도 없습니다 (칩튠 특유의 치찰음이
들어가면 식장이 아니라 던전이 됩니다).

**언제 울릴지를 소리 쪽에 다시 적지 않습니다.** 시각은 타임라인 한 곳에만 있고,
게임이 단계를 넘어가는 순간 `cutbeat` 으로 알려주면 소리 쪽은 그것만 받습니다
(`data/cutSound.js` 가 단계 → 소리 표). 타임라인을 고치면 소리도 따라옵니다.
표에 빠진 단계가 있으면 테스트가 잡습니다.

## 하드모드 — 2회차

보스를 잡고 엔딩을 보면 **타이틀이 아니라 스테이지 1 로 돌아옵니다.** 거기 처음 보는
사람이 하나 서 있습니다.

```
보스 격파 → 엔딩 → 스테이지 1
                   └ NPC 옆에서 점프를 누르면 말을 건다
                     → 옆에 포탈이 열린다
                     → 들어가면 하드모드
```

**NPC 는 말을 안 합니다.** 말풍선 안에 그림 세 장이 지나갑니다 —
트로피(1등은 했다) → 금 간 트로피와 위로 더 뻗는 차트(위가 있다) → 문(저기로 가라).
이 게임은 오프닝부터 엔딩까지 글자 한 줄 없이 굴러왔고, NPC 하나 때문에 그걸 깨지
않았습니다.

말 걸기는 **점프 키 그대로**입니다. 딱 한 번 쓰는 것 때문에 폰 화면에 버튼을
하나 더 붙일 이유가 없습니다.

### 먼저 — 장치 셋이 고장나 있었습니다

처음 만든 하드모드가 안 어려웠던 이유는 설계가 아니라 **장치가 작동하지 않아서**입니다.
숫자로 재 보고서야 알았습니다.

**1. 튕기는 발판이 점프컷에 잘리고 있었습니다.** `player.js` 의 "키를 일찍 떼면 낮게
뜬다" 규칙이 발판이 밀어 올린 속도까지 깎았습니다.

| 발판을 밟았을 때 | 실제로 뜬 높이 |
|---|---|
| 점프키를 안 쥔 채 (거의 항상) | **0.39칸** — 보통 점프(2.95칸)보다 못하다 |
| 우연히 쥐고 있었을 때 | 5.20칸 |

점프컷은 이제 **내가 누른 점프에만** 걸립니다. 게임이 밀어 올린 속도(발판·밟기 반동)는
`player.launched` 가 켜져 있는 동안 안 깎입니다. 덤으로 발판이 **걸어 들어가도**
튀게 했습니다 — 전에는 공중에서 내려앉을 때만 튀어서, 평지를 달리다 밟으면
아무 일도 안 일어났습니다.

**2. 천장 가시는 한 번도 발동한 적이 없습니다.** 가시에서 **4칸 이내**로 들어와야
발동하고 칼날은 **1칸**까지만 내려오는데, 전부 바닥에서 6~7칸 위에 달려 있었습니다.
16개가 전부 그냥 그림이었습니다.

지금은 **창**입니다. 칼날이 **세 칸**을 뻗고 발동 범위도 같이 넓혔습니다 —
천장에 높이 달아놓고도 바닥까지 내리꽂습니다. 그래서 **튕기는 발판으로 솟았다가
꽂히는** 자리도 생겼습니다.

> 그림도 같이 길어졌습니다. 판정은 세 칸인데 그림이 한 칸이면 **보이지도 않는
> 자리에서 죽습니다.** 길이는 이제 `CEIL_BLADE` 한 곳에서만 정합니다.

**3. 무너지는 바닥 밑에 통짜 바닥이 깔려 있었습니다.** `####,,,,####` 아래가
`############` 이라 꺼져도 한 칸 떨어지고 끝이었습니다. 하드모드에서는 밑을
비웠습니다 — 이제 **진짜로 떨어집니다.** (보통 스테이지 1 은 이 장치를 처음
배우는 자리라 일부러 안전하게 둡니다.)

꺼지는 시간도 0.45초 → **0.16초**로 줄였습니다. 전속력이면 한 칸을 0.13초에
지나므로 **달리면 건너지고 멈추면 빠집니다.** 벽에 막혀 멈추는 순간 발밑이
사라지는 연쇄가 여기서 나옵니다.

셋 다 테스트로 못 박았습니다. 눈으로는 "판이 있다"로 보여서 아무도 못 알아챕니다.

### 밀도를 올렸습니다

160칸짜리 판에 앨범이 6마리, 추격 판 셋은 구멍이 **하나도 없는** 통짜 활주로였습니다.
그러니 오른쪽만 눌러도 끝까지 갔습니다.

| | 낭떠러지 | 앨범 | 체크포인트 |
|---|---|---|---|
| ❄️ hard1 | 15 → **23칸** | 6 → **12** | 2 → **4** |
| 🕳️ hard2 | 0 → **22칸** | 6 → **12** | 2 → **4** |
| 🏃 hard3 | 0 → **21칸** | 7 → **11** | 4 → **1** |
| 🔥 hard4 | 0 → **21칸** | 8 → **10** | 5 → **1** |

이 표의 최소치도 테스트가 지킵니다. 다시 밋밋해지면 빌드가 떨어집니다.

### 함정은 혼자 나오지 않습니다 — 짝을 지어 겁니다

함정 하나는 하나씩 처리하면 넘어갑니다. **둘이 짝을 이뤄야** 예상을 벗어납니다.

| 연쇄 | 어떻게 잡는가 | 알면 넘기는 법 |
|---|---|---|
| 솟는 벽 + 무너지는 바닥 | 벽에 막혀 멈추는데 **그 순간 발밑이 꺼진다** | 멈추지 말고 미리 뛴다 |
| 튕기는 발판 + 천장 창 | 위쪽 단이 지름길처럼 보이는데 발판이 창으로 쏘아 올린다 | 위로 안 올라간다 (아래 길은 안전하다) |
| 구멍 착지 + 불쑥 가시 | 건너뛴 **착지 자리**에서 가시가 솟는다 | 한 칸 더 멀리 뛴다 |
| 좌우반전 + 솟는 벽 | 넘어야 하는데 방향이 뒤집혀 있다 | 반대를 누른다 |
| 정전 + 폭탄 | 안 보이는데 위에서 떨어진다 | 그림자는 어둠 속에서도 보인다 |

> **규칙: 알고 있으면 빠져나가는 입력이 반드시 있습니다.** 처음 보면 죽는 게 맞지만,
> 방법이 아예 없으면 그건 어려운 판이 아니라 **못 깨는 판**이고 화면만 봐서는
> 둘이 구분이 안 갑니다. 그래서 테스트가 **아는 사람을 흉내 낸 봇**으로 네 판을
> 실제로 끝까지 굴려봅니다. 봇이 아는 건 딱 둘입니다 — 앞을 보고 뛴다,
> 그리고 **위에 창이 달린 발판만** 피한다.

### 새 함정 — 하늘에서 떨어지는 폭탄

```
     ▼        ▼          ← 폭탄
   ┈┈┈┈    ┈┈┈┈          ← 떨어질 자리 (0.6초 먼저 뜬다)
  ────────────────
```

`B` 칸을 밟으면 5초 동안 하늘에서 떨어집니다. **그림자가 먼저 뜨고 폭탄은 나중**입니다 —
예고 없이 하늘에서 죽으면 트롤이 아니라 그냥 불합리한 게임입니다.

떨어지는 자리는 **4칸 격자에 붙습니다.** 플레이어 위치에 그냥 더하면 달리는 동안
기준이 밀려서 앞뒤 폭탄이 한두 칸 차이로 겹치고, 그러면 설 자리가 없어져
못 지나가는 구간이 됩니다. 격자에 붙이면 두 폭탄은 같은 칸이거나 최소 4칸 떨어집니다.
이것도 테스트가 지킵니다.

**좌우반전(`R`)과 정전(`@`)** 도 하드모드에 깔았습니다. 만들어만 두고 하드에서는
한 번도 안 썼던 장치입니다. 둘 다 **평지에서만** 겁니다 — 안 보이는 채로 구멍에
빠지거나 반대로 걸어 떨어지면 알아도 못 넘는 자리가 됩니다.

### 판 넷 — 앞의 둘과 뒤의 둘은 결이 다릅니다

기존 판을 어렵게 고친 게 아닙니다. **길을 외운 사람에게 같은 지형은 어렵지 않습니다.**

넷을 다 "함정 많고 어려운 판"으로 만들면 뒤로 갈수록 지칩니다. 그래서 뒤의 둘은
아예 성격을 바꿨습니다.

| 판 | 무대 | 결 |
|---|---|---|
| ❄️ | 얼음 | **미끄러져 떨어진다.** 얼음이 끝나는 자리마다 낭떠러지 |
| 🕳️ | 낮은 천장 | **위에서 온다.** 천장 가시 다섯, 발판으로만 건너는 구멍 셋 |
| 🏃 | 숲 | **멈추면 죽는다** — 추격을 배우는 판. 구멍·단차·벽 |
| 🔥 | 마지막 질주 | **멈추면 죽는다** — 전부 섞고 가속 구간 둘 |

> 🕳️ 판은 **튕기는 발판이 주인공**입니다. 여섯 칸·일곱 칸짜리 구멍은 뛰어서는
> 못 넘고, 발판으로 5.2칸을 솟아 위쪽 길로만 건널 수 있습니다. 보통 점프로는
> 그 발판에 절대 못 닿게 높이를 맞춰 뒀습니다.

### 3·4판 — 뒤에서 보스가 쫓아옵니다

```
        [거대 합체로봇]  →→→        나  →→→→→→→   골
         ↑ 108px/s                   ↑ 124px/s
         닿는 자리는 세로 띠 하나     완벽히 달려야 겨우 벌린다
```

판이 시작하는 순간부터 화면 왼쪽에서 3페이즈 합체로봇이 밀고 들어옵니다.
새로 그린 게 아니라 **보스전 배경으로 이미 굽던 그림을 옆으로 세운 것**입니다.
그림은 화면 절반을 덮어도 **죽는 자리는 세로 띠 하나**입니다 — 저기 닿으면
죽는다가 헷갈리면 그건 어려운 게 아니라 억울한 것입니다.

처음에는 82px/s 였는데, 그러면 잘 달리는 사람은 로봇을 **한 번도 못 보고** 판을
끝냈습니다. 쫓기는 판인데 쫓기는 느낌이 없었습니다. 지금은 108 이고, 시작 간격도
360 → **200px** 로 좁혔습니다. 완벽하게 달려도 제일 붙을 때 **50px** 까지 옵니다.

> **안 넘기는 선 하나: 쫓아오는 속도(108)는 달리기(124)보다 느립니다.**
> 기본 속도가 달리기보다 빠르면 한 번 잃은 거리를 **영영 못 되찾아서**,
> 실수 한 번에 판이 끝납니다. 잡히는 건 달리기가 느려서가 아니라 **벽에 막혀
> 멈췄을 때, 구멍을 못 넘었을 때, 함정에 걸렸을 때**여야 합니다.
>
> 다만 이 부등호만으로는 재미를 보장 못 합니다. 그래서 테스트가 **실제로 봇을
> 굴려서** 잽니다 — 잘 달리고 잘 뛰면 골까지 가되, **완주 간격이 60~420px**
> 사이여야 통과입니다. 너무 벌어져도(긴장이 없다) 잡혀도(불합리하다) 떨어집니다.

**지형이 발목을 잡습니다.** 예전 추격 판은 구멍이 하나도 없는 평지라 오른쪽만
누르면 됐습니다. 지금은 구멍 26칸, 단차, 천장 가시, 발판으로만 건너는 구간이
깔려 있어서 **달리면서 계속 뛰어야** 합니다.

> 솟는 벽은 **구멍에서 떨어뜨려** 놓습니다. 구멍 바로 앞에 두면 벽을 넘자마자
> 구멍에 빠져서, 어려운 게 아니라 못 넘는 자리가 됩니다. 천장 가시도 구멍
> 가장자리 위에 두지 않습니다 — 뛰어올라야 하는데 위가 막혀 있으면 뛸 수가 없습니다.
> 둘 다 테스트가 지킵니다.

- 카메라가 추격 판에서만 **70px 앞으로** 밀립니다. 뒤가 안 보이면 얼마나 붙었는지
  모르고, 그건 긴장이 아니라 답답함입니다.
- 화면 왼쪽 가장자리의 **띠**가 거리입니다. 보라 → 노랑 → 빨강. 바짝 붙으면
  가장자리가 같이 번쩍입니다. **숫자는 안 씁니다** (이 게임엔 글자가 없습니다).
- 체크포인트가 판마다 **딱 하나**입니다. 그것도 판 한가운데 하나뿐 — 스피드런은
  되돌아가는 벌이 세야 긴장이 삽니다. 다섯 개나 두면 잡혀도 바로 앞에서 다시
  시작해서 쫓기는 느낌이 안 났습니다.

추격 판에는 **깜빡이는 발판과 가짜 체크포인트를 안 씁니다.** 둘 다 서서 기다려야
하는 장치인데, 기다릴 수 없는 판에 기다리는 장치를 두면 그냥 못 깨는 자리가 됩니다.

**잡히면 컷신입니다** — 왼쪽부터 그림자가 덮이고, 거대한 손이 내려와 붙잡고,
암전. **대사는 없습니다.** 끝나면 지금까지의 죽음과 **같은 길**로 갑니다 —
차트아웃이 오르고 체크포인트에서 살아납니다. 새 길을 안 만들었으니 "죽으면
체크포인트"라는 이미 배운 규칙이 그대로 통합니다.

> 살아날 때 **쫓아오는 것도 360px 뒤로 물러납니다.** 시작 간격(200)보다 넉넉합니다 —
> 눈뜨자마자 다시 잡히면 빠져나올 수 없는 판이 되기 때문입니다.

화면을 강제로 미는 **자동 스크롤은 안 씁니다.** 카메라가 밀면 플레이어가 화면 밖에서
죽습니다. 쫓아오는 것이 밀어붙이는 걸로 충분하고, 그쪽이 훨씬 공정합니다.

### 함정 아홉 종이 늘었습니다

| 글자 | 이름 | 하는 짓 |
|---|---|---|
| `:` | **깜빡이는 발판** | 주기적으로 사라졌다 나타난다. 건널 틈을 재야 한다 |
| `;` | **가짜 체크포인트** | 진짜와 똑같이 생겼는데 **저장이 안 되고** 사라진다 |
| `_` | **미끄러운 바닥** | 마찰이 1/8. 놓아도 한참 밀린다 |
| `!` | **튕기는 발판** | 점프보다 훨씬 높이 튄다. 위에 뭐가 있는지 보고 밟아야 한다 |
| `T` | **천장 가시** | 아래를 지나가면 내려온다 |
| `>` | **가속 구간** | 여기부터 쫓아오는 것이 3초 동안 빨라진다 (108 → 120) |
| `B` | **폭탄 구간** | 5초 동안 하늘에서 떨어진다. 그림자가 먼저 뜬다 |
| `R` | **좌우반전** | 4초 동안 좌우가 뒤바뀐다 |
| `@` | **정전** | 3.5초 동안 화면이 깜깜해진다 |

**전부 예고가 있습니다.** 깜빡이는 발판은 보이는 대로 깜빡이고, 가짜 체크포인트는
한 번 당하면 붉게 표시되고, 쫓아오는 로봇은 화면에 계속 보입니다. 원칙은 그대로입니다 —
예고 없이 들어오면 트롤이 아니라 그냥 불합리한 게임입니다.

> 함정 표시를 기억하는 열쇠에 **스테이지 이름**이 붙습니다. 안 그러면 같은 칸이면
> 같은 열쇠라, 하드모드 (12,9) 가 스테이지 1 에서 당한 표시를 물려받아 처음부터
> 붉게 뜹니다. 보통 판은 예전 형식 그대로 둡니다 — 형식을 바꾸면 이미 저장된
> 표시가 전부 안 맞게 됩니다.

### 보스는 4페이즈

체력이 **12** (페이즈당 세 대는 그대로). 레이저를 **1페이즈부터** 쓰고,
4페이즈에서는 **기둥이 둘**이 되어 양쪽 끝에서 안쪽으로 훑어 옵니다.

공정함은 그대로입니다 — 훑는 속도는 여전히 달리기보다 느리고, **두 기둥 사이에는
반드시 설 자리가 남습니다.** 둘 다 테스트가 지킵니다. 가운데가 다 덮이면 그건
어려운 게 아니라 그냥 죽으라는 것입니다.

전환 컷신에서 **새 몸을 그리지 않습니다.** 있는 로봇을 벌겋게 달구고 이음새에서
빛이 새어 나오게 합니다 — 여기서 또 새 형태를 만들면 3페이즈 합체가 시시해집니다.

### 기록은 따로 남습니다

하드 기록은 `bestHardTimeMs` 로 가고 보통 기록을 덮지 않습니다. 안 나누면
"최고 기록"이 무슨 판의 기록인지 알 수 없게 됩니다. 타이틀에 ★ 로 같이 뜹니다.

> **저장 버전은 안 올렸습니다.** 이 게임의 `deserialize` 는 버전이 다르면 던지고
> `loadSave` 가 그걸 삼켜 빈 저장을 줍니다 — 버전을 올리는 순간 기존 플레이어의
> 기록·해금·설정이 **전부 조용히 지워집니다.** 칸만 더하면 옛 저장도 그대로 열립니다.

### 레벨 고치기

`src/data/stages.js` 는 **20칸 × 14줄짜리 구간(chunk)** 을 옆으로 이어 붙여 스테이지를 만듭니다.
눈으로 보고 고칠 수 있고, 줄 수나 칸 수가 틀리면 불러올 때 바로 알려줍니다.

```
' ' 빈 칸      '#' 땅          '=' 관통 발판     '?' 아이템 블록
'X' 낚시 블록  'I' 투명 블록   '%' 가짜 발판     '~' 역주행 바닥
'^' 가시       'v' 불쑥 가시   '*' 재생수(음표)  'S' 시작
',' 무너지는 바닥  '|' 솟아오르는 벽  'R' 역재생 구간  '@' 정전 구간
'C' 체크포인트 'G' 골          'F' 도망가는 가짜 골
'a'~'q' 앨범 17종
```

테스트가 다음을 검사합니다: 스테이지마다 시작점·골·체크포인트가 있는지, 쓴 앨범 글자가 실제로
존재하는지, 구멍이 한 번에 건널 수 있는 폭인지(넓다면 위에 딛을 발판이 있는지),
**솟는 벽 위가 막혀 있지 않은지**(막히면 길이 영영 끊긴다), **구간 트리거가 밟을 수 있는 자리인지**,
그리고 **역재생·정전이 반드시 저절로 풀리는지**(영구히 걸리면 게임이 끝난다).

컷신도 같은 식으로 못 박아 뒀습니다: 세 컷신이 **반드시 저절로 풀리고**(안 풀리면 게임이 영영 멈춘다),
도는 동안 **체력도 플레이어도 안 움직이고**, 건너뛰기가 먹고, 격파하면 엔딩 컷신을 거쳐
통계가 그대로 넘어옵니다.
